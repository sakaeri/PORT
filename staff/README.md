# PORT 受付（スタッフ用アプリ）

依頼主向けアプリ（`../`）と同じSupabaseプロジェクトを使う、受付・経営（owner/reception）向けの業務画面。
制作者（creator）向けの画面は別アプリとして別途作る想定で、ここには含まない。

## セットアップ

依頼主アプリと同じSupabaseプロジェクトのURL・キーを使う。

```
cp .env.local.example .env.local
# NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY / SUPABASE_SERVICE_ROLE_KEY を埋める
npm install
npm run dev
```

スタッフアカウントは自己登録ができない（意図的）。Supabaseダッシュボードの Authentication → Users から
メール＋パスワードでユーザーを作成し、`profiles` テーブルに `role='owner'` または `'reception'` の行を
手動で追加する必要がある（招待フローは未実装、今後の課題）。

## 実装状況

**できているもの（フェーズ0）**
- ログイン（メール＋パスワード）
- owner/reception 以外（creator など）はアクセス拒否
- サイドバーの骨組み（依頼主／案件トーク／売上・実績／スタッフ／メニュー管理）
- テーマ切替（ダーク/ライト）
- 「依頼主」一覧（実データ、名前・お問い合わせ番号・担当者を表示するだけ）

**まだのもの**
- 依頼主とのトーク詳細（見積もり発行・返信・完了報告・返金）
- 案件トーク（複数人での社内やり取り）
- 売上・実績集計
- スタッフの詳細（契約・報酬・稼働・評価）
- メニュー管理（会社情報・受付メニュー・返信テンプレ・契約書テンプレ・返金ポリシー）
- 決済（銀行振込の手動確認は近いうちに対応、カード決済のAPI連携は保留）

## デプロイ

依頼主アプリとは別のVercelプロジェクトとして、この `staff/` フォルダを「Root Directory」に指定してデプロイする
（同じGitHubリポジトリ内の別フォルダを、別プロジェクト・別URLとしてデプロイする形）。
